Selected Projects

프로젝트 사례

01 / REAL-TIME SYSTEM

멀티 인스턴스 환경의 실시간 알림 시스템

Redis StreamsPub/SubSSEBackfill

사용자의 챕터·미션 완료 이벤트를 실시간으로 전달하면서, 재연결이나 멀티 인스턴스 환경에서도 이벤트가 유실되지 않는 구조가 필요했습니다.

PROBLEM

단일 인스턴스 전제의 실시간 전달은 scale-out과 네트워크 재연결 상황에서 순서와 유실을 보장하기 어려웠습니다.

APPROACH

Redis Streams를 이벤트 원장으로 두고 Pub/Sub과 SSE를 연결했습니다. Last-Event-ID와 lastSentId를 기준으로 backfill을 구현했습니다.

RESULT

일관된 수신 경험

멀티 인스턴스와 재연결 상황에서도 놓친 이벤트를 복구할 수 있는 기반을 마련했습니다.

02 / PERFORMANCE

혈당 그래프 API 응답 속도 개선

Redis CacheMySQLConcurrency Control

혈당 데이터 조회는 사용자 경험과 직결되지만, 동일한 요청이 반복되고 데이터 집계 비용이 커지면서 응답 지연이 발생했습니다.

PROBLEM

반복 조회와 중복 요청이 DB에 부담을 주고, 그래프 화면의 초기 응답을 늦추고 있었습니다.

APPROACH

공통 Redis 캐시 구조를 모듈화하고 중복 요청을 제어했습니다. 병목 쿼리를 분석해 MySQL 쿼리를 튜닝했습니다.

RESULT

2.5s → 0.5s

응답 속도를 약 80% 개선하고 다른 조회 API에도 재사용 가능한 캐시 구조를 만들었습니다.

03 / ASYNC PIPELINE

동기 처리에서 재처리 가능한 비동기 파이프라인으로

CronAWS SQSConsumerIdempotency

혈당 갱신·보정·후처리가 하나의 동기 흐름에 묶여 있어 일부 단계의 장애가 전체 처리를 지연시키고 재처리를 어렵게 만들었습니다.

PROBLEM

처리 단계가 강하게 결합되어 장애 격리와 실패 지점별 재처리가 어려웠습니다.

APPROACH

Cron에서 작업을 발행하고 SQS Consumer가 후처리하도록 분리했습니다. idempotency key와 FIFO로 중복과 순서를 제어했습니다.

RESULT

재처리 가능한 구조

처리 책임을 단계별로 나누어 장애 격리와 확장성을 높였습니다.

04 / ENERGY SAAS

에너지 SaaS 통계 API와 데이터 수집 개선

MongoDBRedisS3Jenkins

초당 원시 데이터를 매 요청마다 집계하던 통계 API와, 실패 시 전체 흐름을 다시 확인해야 했던 수집 배치를 개선했습니다.

APPROACH

1분 평균을 선집계해 Redis에 저장하고, 수집·전처리·적재를 모듈로 분리해 실패 지점별 재시도와 Slack 알림을 구성했습니다.

OPERATION

MongoDB Atlas 샤딩과 인덱스 튜닝, Docker·ECR·Jenkins·ECS 배포 자동화를 적용했습니다.

RESULT

4–5s → 0.9s

대시보드 응답 개선, 비용 30% 절감, 데이터 수집 실패율 5%에서 0.2%로 개선했습니다.

05 / SEARCH & ETL

대규모 문서 검색과 색인 파이프라인

ElasticsearchLogstashApache NiFiSpark SQL

수천만 건의 거래 데이터와 5억 건 이상의 첨부파일을 다루는 검색·색인 시스템에서 처리 시간과 실패 재처리 문제를 해결했습니다.

APPROACH

RDB 로직을 Spark SQL과 Elasticsearch로 재구현하고, 대용량 색인 배치와 실패 재처리 전략을 설계했습니다.

PIPELINE

NiFi 기반 수집·가공·적재·추출·전송 단계를 자동화해 원천 데이터부터 검색 결과까지의 흐름을 관리했습니다.

RESULT

90일 → 30일

전체 색인 기간을 단축하고 운영자가 수동으로 복구하던 구간을 자동화했습니다.

Slack Slash CommandCronKakao AlimtalkAudit Log
